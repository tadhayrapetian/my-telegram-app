# Slate — сервер

Аккаунты преподавателей, изоляция данных и лимиты тарифов. Без единой внешней
зависимости: только встроенные модули Node 22 и SQLite, который в Node уже есть.
Никакого `npm install`.

## Запуск

```bash
cd slate-server
node --no-warnings server.js
```

Откроется на http://localhost:3000. Данные — в `slate-server/data/`
(файл `slate.db` и ключ подписи сессий `secret.key`).

При запуске сервер печатает второй адрес — для той же домашней сети:

```
[slate] сервер на http://localhost:3000
[slate] с телефона и планшета в той же сети: http://192.168.1.42:3000
```

По этому адресу Slate открывается **с айпада и телефона**, пока компьютер
включён и подключён к тому же Wi-Fi. Регистрация — `.../app#signup`.
В первый раз macOS спросит, разрешить ли входящие подключения, — разрешите.

Нужен **Node 22.5 или новее** — в нём есть встроенный SQLite. Проверить: `node -v`.

Переменные окружения:

| Переменная | Смысл |
|---|---|
| `PORT` | порт, по умолчанию 3000 |
| `SLATE_DATA` | папка с данными, по умолчанию `./data` |
| `SLATE_DEV_CODES` | `1` — показывать код на экране даже при настроенной почте (отладка) |
| `SLATE_MAIL` | `smtp`, `resend`, `brevo` или `custom` — чем слать письма |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` | почтовый ящик и пароль приложения |
| `SLATE_TG_API` | адрес переходника к Telegram, если прямой доступ закрыт |
| `SLATE_ADMIN` | почта хозяина сервиса — открывает страницу `/admin` |
| `RESEND_API_KEY` / `BREVO_API_KEY` | ключ выбранной службы |
| `SLATE_MAIL_FROM` | отправитель, например `Slate <hello@getslate.com>` |

## Если домена нет

Домен покупать не обязательно — ссылку можно получить бесплатно, двумя путями.

**Постоянный адрес без карты и без домена.** Двойной клик по `public.command`:
он поднимает Slate и выставляет его наружу через Tailscale Funnel. Адрес
получается вида `https://macbookpro.ваша-сеть.ts.net` — он **не меняется**,
его можно дать ученикам один раз. Бесплатно, регистрация по Google или
GitHub, карта не нужна, порты открывать не надо. Один раз:

```bash
brew install tailscale
sudo tailscale up            # откроется браузер, вход через Google
```

Работает, пока включён компьютер и открыто окно. Нужен круглосуточный
адрес — нужен сервер, и только для него понадобится карта или оплата.

**Быстрая разовая ссылка.** Двойной клик по `share.command`: он запускает
Slate и просит у Cloudflare временный адрес вида
`https://что-то.trycloudflare.com`. По нему программа открывается с айпада,
телефона и у любого, кому вы дали ссылку. Нужен один раз установленный
`cloudflared` (`brew install cloudflared`). Пока окно открыто — ссылка
работает; закрыли или выключили компьютер — перестала, и в следующий раз
адрес будет другой. Годится показать, проверить, дать сестре на вечер.

**С сервером, бесплатный постоянный адрес.** На [duckdns.org](https://duckdns.org)
заводится имя вида `myslate.duckdns.org`, туда вписывается IP вашего сервера —
это бесплатно и навсегда. Дальше обычная установка, сертификат выпустится и на
такое имя:

```bash
sudo bash install.sh myslate.duckdns.org
```

Свой домен можно купить позже и направить на тот же сервер: данные, аккаунты
и ссылки на кабинеты при этом никуда не денутся, поменяется только адрес.

## Админка сервиса

Страница `/admin` — для хозяина сервиса, а не для преподавателей. Показывает
все школы: кто зарегистрировался, сколько у кого учеников и занятий, когда
последний раз заходили, подключён ли телеграм, — и позволяет менять тариф
любой школе одной кнопкой (кабинеты учеников появляются и исчезают сразу).

Доступ по адресу почты, отдельного пароля нет:

```
SLATE_ADMIN=вашапочта@gmail.com
```

Несколько адресов — через запятую. Пока переменная пуста, `/admin` закрыта
для всех. Вошедший не хозяин получает «нет прав», не вошедший — приглашение
войти.

## Напоминания в Telegram

Работают без домена и без белого IP: бот сам ходит за сообщениями, поэтому
Slate может стоять хоть на ноутбуке.

1. В Telegram напишите **@BotFather** → `/newbot` → придумайте имя и адрес
   бота. Он выдаст токен вида `123456:AA…`.
2. Впишите его в `/opt/slate/slate.env` (или в окружение при запуске):

```
SLATE_BOT_TOKEN=123456:AA…
```

3. `systemctl restart slate` — в логе появится «бот @имя на связи».

### Если сервер не пускают к Telegram

С российских дата-центров `api.telegram.org` обычно недоступен — в логе будет
`сеть — ETIMEDOUT`. Проверить прямо на сервере:

```bash
curl -sS -m 10 -o /dev/null -w '%{http_code}\n' https://api.telegram.org/
```

Лечится переходником на Cloudflare Workers: бесплатно, карта не нужна.
Код и пошаговая инструкция — в файле `telegram-proxy.worker.js`. Коротко:
создаёте воркер, вставляете туда этот файл, получаете адрес
`https://имя.логин.workers.dev` и добавляете в `/opt/slate/slate.env`:

```
SLATE_TG_API=https://имя.логин.workers.dev
```

После `systemctl restart slate` в логе появится «бот @имя на связи».
Адрес воркера держите при себе: через него ходит токен бота.

Дальше преподаватель нажимает **Настройки → Подключить Telegram**, ученик —
кнопку в своём кабинете: обе дают ссылку на бота, где надо нажать «Старт».
Отключить можно кнопкой в программе или командой `/stop` самому боту.

Что и когда уходит:

| кому | когда | что |
|---|---|---|
| ученику | накануне после 18:00 | занятие завтра, время и домашнее задание |
| ученику | за два часа | напоминание и ссылка на онлайн-занятие |
| ученику | сразу | сообщение от преподавателя |
| преподавателю | утром | занятия на сегодня списком |
| преподавателю | после 10:00 | вчерашние неотмеченные занятия |
| преподавателю | сразу | сообщение от ученика |

Одно и то же напоминание дважды не приходит: отправленное помечается
в базе. Если бот заблокирован или чат удалён, привязка снимается сама.

## Почта: чтобы регистрироваться могли посторонние

Пока почта не настроена, код входа показывается прямо на экране. Для себя это
удобно, но чужой человек так зарегистрируется под любым адресом — значит, перед
тем как открывать регистрацию людям, нужна отправка писем.

### Без домена: через свой почтовый ящик

Подходит, когда домена нет (например, адрес на duckdns). Письма идут от вашего
обычного ящика, подтверждать нечего.

Gmail: включите двухэтапную проверку, создайте **пароль приложения** на
[myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords)
и впишите в `/opt/slate/slate.env`:

```
SLATE_MAIL=smtp
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=вашпочта@gmail.com
SMTP_PASS=пароль-приложения
```

Яндекс — `smtp.yandex.ru`, Mail.ru — `smtp.mail.ru`, порт тот же, пароль тоже
отдельный «для приложений». Обычный пароль от почты не подойдёт и не должен:
его нельзя хранить на сервере.

Ограничение Gmail — около 500 писем в сутки, для кодов входа этого хватает
с большим запасом. Пароль уходит только по шифрованному каналу: если сервер
не предложит STARTTLS, Slate откажется отправлять.

### Со своим доменом: почтовая служба

1. Заведите аккаунт в [resend.com](https://resend.com) (3000 писем в месяц
   бесплатно) или [brevo.com](https://brevo.com) (300 писем в день).
2. Подтвердите там свой домен — служба покажет три DNS-записи, их надо
   добавить у регистратора домена. Без этого письма уходят в спам.
3. Создайте ключ и впишите в `/opt/slate/slate.env` на сервере:

```
SLATE_MAIL=resend
RESEND_API_KEY=re_xxxxxxxxxxxx
SLATE_MAIL_FROM=Slate <hello@getslate.com>
```

4. `systemctl restart slate`

После этого код уходит письмом, на экране его больше нет, а в логе сервера
видно `письма через resend`. Если служба ответит ошибкой, сервер вернёт 502
и напишет причину в лог — молча «отправленных» писем не бывает.

## Как это работает

**Вход по коду.** Преподаватель вводит почту, сервер присылает шестизначный код,
код меняется на сессию в защищённой cookie на 30 дней. Пароли не хранятся вовсе —
нечего утекать. Пока доставка кодов не подключена, код возвращается прямо в ответе
и пишется в лог сервера; на боевом сервере это выключается одной переменной.

**Регистрация и вход — разные вкладки.** Регистрация спрашивает имя и почту
и заводит школу, где этот человек — владелец; вход с незнакомого адреса аккаунт
не создаёт, а предлагает зарегистрироваться (и наоборот).
Владелец на тарифе Studio добавляет преподавателей по почте — каждый заходит под
собой и **видит только своих учеников**. Данные каждого преподавателя лежат
отдельным документом, чужой недоступен даже по прямому запросу к API.

**Лимиты тарифов проверяет сервер, а не браузер.** Это принципиально: браузер можно
открыть в консоли и поправить что угодно. Сервер отклоняет сохранение, если
учеников больше, чем позволяет тариф, или если на бесплатном появились оплаты
и абонементы.

| Тариф | Учеников | Преподавателей | Оплаты, абонементы, кабинет, отчёты |
|---|---|---|---|
| Free | 2 | 1 | нет |
| Pro | 15 | 1 | да |
| Studio | без ограничений | до 20 | да |

Тариф пока переключается вручную в настройках — биллинга ещё нет, и это честно
написано в интерфейсе. Здесь же он потом и появится.

**Кабинет ученика.** У каждого ученика свой адрес `/s/<токен>` и код из карточки.
Токен вычисляется от идентификатора преподавателя и ученика, пересобирается при
каждом сохранении. Ссылку и код видно в карточке ученика — копируются одной кнопкой.

**Защита от затирания.** У документа есть версия. Если вы открыли программу
на ноутбуке и на телефоне, и на телефоне сохранилось раньше, ноутбук получит отказ,
перечитает свежие данные и покажет об этом сообщение — вместо тихой потери работы.

## Интерфейс

`public/index.html` — та же программа, что работает офлайн, только теперь она
определяет режим при запуске: открыта с сервера — работает через API и требует
вход, открыта как файл — живёт в localStorage, как раньше. Файл один, копия в
`slate-app/` идентична.

`public/portal.html` — отдельная лёгкая страница кабинета ученика.

`public/landing.html` — страница продукта. Это копия `slate-landing/index.html`,
в которой якорные ссылки кнопок «Начать бесплатно» и «Войти» заменены на `/app`.
Правите лендинг — перенесите правку и сюда.

Адреса сайта:

| Адрес | Что отдаёт |
|---|---|
| `/` | страница продукта с тарифами |
| `/app` | программа: вход, а после входа — расписание и всё остальное |
| `/s/<токен>` | кабинет ученика |

## Файлы, фото и переписка

Появляются на тарифе Pro и выше — вместе с кабинетом ученика.

**Файлы.** В карточке ученика — раздел «Файлы»: загружаете сколько угодно,
по 15 МБ на файл и 300 МБ на преподавателя. Принимаются картинки, PDF, документы
Word, текст, аудио и mp4; исполняемые файлы сервер отклоняет. PDF и картинки
открываются прямо в программе, без скачивания — для PDF встроенный просмотрщик
браузера, он есть и в Safari на айфоне.

**Фото ученика.** Ученик добавляет своё фото в кабинете, оно появляется у вас
в карточке.

**Переписка.** Отдельная лента между вами и учеником: текст и вложения. У вас —
в карточке ученика, у него — в кабинете. К сообщению можно прикрепить файл
кнопкой со скрепкой.

Доступ к файлу проверяется на сервере: преподаватель видит только свои,
ученик — только те, что относятся к нему. Посторонний по прямой ссылке
получает отказ.

Кабинет теперь помнит вход на неделю: код спрашивают один раз, дальше
ученик просто открывает ссылку.

## Проверка

Тесты в репозитории не лежат отдельным пакетом, но проверялось следующее и всё
проходит: вход по коду, отказ на неверный код, недоступность данных без сессии,
лимит бесплатного тарифа на третьем ученике, запрет оплат на бесплатном, снятие
ограничений на Pro, отказ на шестнадцатом ученике, запрет второго преподавателя
на Pro, изоляция данных между преподавателями, закрытость сводки школы от
преподавателя, кабинет по токену с проверкой кода, расчёт баланса на сервере,
отклонение устаревшей версии документа, выход из сессии.

Отдельно проверены файлы и переписка: загрузка PDF, отказ на исполняемом файле,
список файлов у ученика, сообщение с вложением, вход ученика в кабинет по коду
и повторный вход по cookie, загрузка фото, ответ ученика, выдача файла по ссылке,
отказ постороннему и чужому преподавателю, закрытие файлов на бесплатном тарифе.
В браузере: раздел файлов в карточке, загрузка и просмотр PDF внутри программы,
переписка в обе стороны, фото ученика, просмотрщик в кабинете на телефоне.

## Боевой сервер

Хватает самого маленького VPS: 1 ГБ памяти достаточно, 2–4 ГБ — с запасом.

```bash
# на сервере
apt update && apt install -y nodejs   # нужен Node >= 22.5, при необходимости с nodesource
adduser --system --group slate
mkdir -p /opt/slate && chown slate:slate /opt/slate
# скопировать сюда slate-server/
```

`/etc/systemd/system/slate.service`:

```ini
[Unit]
Description=Slate
After=network.target

[Service]
Type=simple
User=slate
WorkingDirectory=/opt/slate
Environment=PORT=3000
Environment=SLATE_DATA=/opt/slate/data
Environment=SLATE_DEV_CODES=0
ExecStart=/usr/bin/node --no-warnings /opt/slate/server.js
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now slate
```

HTTPS проще всего через Caddy — сертификат он получает сам:

```
getslate.com {
    reverse_proxy 127.0.0.1:3000
}
```

**Бэкапы.** Всё в одном файле, поэтому раз в сутки по cron:

```bash
sqlite3 /opt/slate/data/slate.db ".backup '/opt/slate/backup/slate-$(date +%F).db'"
```

и копию — в объектное хранилище. Это важнее размера сервера.

## От нуля до сайта на getslate.com

Чтобы заходить с айпада и телефона под своим логином, программа должна стоять
на сервере. На iOS запустить её локально нельзя — Node там не существует.

Весь путь — минут двадцать, из них девятнадцать это ожидание.

**1. Сервер.** Закажите VPS: Hetzner CAX11 (2 ядра, 4 ГБ, около €4 в месяц) или
любой другой с Ubuntu 24.04. На почту придёт IP-адрес и пароль root.

**2. Домен.** В панели регистратора getslate.com добавьте A-запись:

```
Тип: A    Имя: @      Значение: IP вашего сервера
Тип: A    Имя: www    Значение: IP вашего сервера
```

Подождите 10–15 минут, пока запись разойдётся.

**3. Скопируйте папку на сервер.** С макбука, из каталога проекта:

```bash
scp -r slate-server root@IP_СЕРВЕРА:/root/
```

**4. Установите.** Зайдите на сервер и запустите скрипт:

```bash
ssh root@IP_СЕРВЕРА
cd /root/slate-server
sudo bash install.sh getslate.com
```

Скрипт сам поставит Node 22 и Caddy, поднимет службу, получит сертификат HTTPS,
закроет лишние порты и настроит ежедневный бэкап базы. Повторный запуск ничего
не ломает — им же и обновляетесь.

**5. Откройте https://getslate.com** с любого устройства, включая айпад.

**Как войти в первый раз.** Доставка кодов ещё не подключена, поэтому код входа
пишется в лог сервера. Введите почту на сайте, а код посмотрите так:

```bash
journalctl -u slate -f | grep "код входа"
```

Это временно: как только появится Telegram-бот, коды будут приходить в мессенджер
и вам, и вашим преподавателям.

**Обновление до новой версии:**

```bash
scp -r slate-server root@IP:/root/ && ssh root@IP "cd /root/slate-server && sudo bash install.sh getslate.com"
```

Данные при обновлении не трогаются — они лежат отдельно, в `/opt/slate/data`.
